# Cells in Swift

A Swift package of two products over this repository: `Cells`, the binding over the engine (`rust/`) behind its C ABI, and `CellsScripts`, a script's TypeScript read as TypeScript reads it. A table or a chart drawn over them belongs to the app that draws it ([Cells.app](https://github.com/adriangalilea/untitled/tree/main/apps/cells) draws them with swift-utils' InkTable and InkCharts).

**Depended on by path, from a checkout:** an app's `project.yml` or `Package.swift` names `<cells checkout>/swift`. The package links the engine built from that same checkout, `rust/target/apple/CellsCore.xcframework`, so the engine, the binding and the app change together with nothing published between them. `rust/cells-ffi/build-apple.sh` builds it, incrementally (an app's build runs it when the engine's source changed); without it the package stops and says so. macOS only, arm64, all macOS 27 runs on.

**Not built, deliberately:** depending on this package by URL, from a project without a checkout (another developer's app, a CI machine). It would take a `Package.swift` at the repository's root naming the engine as a release asset (`url:`, `checksum:`) and a workflow that builds and publishes it. Built when Cells is offered as a library, not before. Another platform the same way: a slice in `build-apple.sh`, when an app on it links the binding.

```sh
rust/cells-ffi/build-apple.sh          # the engine, for this package
swift test --package-path swift        # the binding's laws and the conformance suite
swift/scripts/palette.sh               # Cells.Palette from syntaxes/palette.json
swift/scripts/typescript.sh            # CellsScripts' TypeScript, at its pinned version
```

## Cells

Data and its logic in one plain-text file ([SPEC.md](../SPEC.md)): a table whose header cells carry their column's type and formula, `name:type=formula`, read and written by the one engine every surface uses. One file, never a sidecar.

```swift
import Cells

var doc = Cells.Document(reading: "item:text!,cost:EUR>=0,paid:yes/no\nfuel,84.20,yes\n")
doc.value(row: 0, column: 1)        // .success(.money(84.20, currency: "EUR"))
doc.problems.map(doc.describe)      // ["row 1, cost: \"8x.50\" is not a number", …]
try doc.set(row: 0, column: 1, to: "90.00")  // `` `=96.75 / 3` `` is the cell's own formula
try doc.setFormula("cost * 2", column: 1)    // its column's, after its type's `=`
doc.moveRows(fromOffsets: [3], toOffset: 0)   // insertRows, removeRows: the file read again
doc.text                            // the file: every unchanged record its own bytes
if case .decimal(let cost) = doc.values(column: 1) { cost.double(0) }  // the engine's buffer, in place
let csv = Cells.Document(reading: text, as: .plain())  // a .csv by the delimiter its lines agree on
let books = Cells.Document(reading: data, at: url)     // its imports followed from the disk
```

- **The header language**: a base (`text`, `int`, `num`, `pct`, `bool`, `date`, `time`, `datetime`, `url`, `email`, `id`, or an ISO 4217 code for money), choices (`travel|stay`), a boolean in the file's own words (`yes/no`), bounds (`>=0`, `0..100`, on text its length), a format (`date(DD/MM/YYYY)`), a key of another table (`accounts.account`), `!` the key and `?` optional, then a formula after `=` (`total:EUR=cost * qty`). Every shorthand has its word (`text key`, `one of travel stay`, `bool yes no`, `EUR min 0`, `num between 0 and 100`). `Cells.parseType` and `document.parseType` (its named types known) read one; `Cells.shorthand(type, names:)` is the engine's canonical spelling, what a writer changing a type writes.
- **Formulas**: a column's (`columns[c].formula`, `cost * qty`) computes every cell of it left blank, a written one its row's override; a cell's own, `` `=96.75 / 3` ``, computes that cell. `origin(row:column:)` says which a value is: `.written`, `.formula` or `.cell`. `setFormula(_:column:)` sets or takes out a column's, its type kept; `setType` keeps the formula; `setSpelled("EUR>=0 = cost * qty", column:)` sets both as a person writes them (its header cell, or its declaration in the prelude). Both throw the engine's reason (`no column "qtty"`) when the formula does not read, names what is not there or gives what the column cannot hold, the document as it was. `reads(row:column:)` is what a computed cell reads, each column and the rows of it. SQL's scalar expressions, in exact decimal (SPEC.md, Formulas).
- **The prelude**: named types (`names`), imports, tables written inline or filled by a script, columns declared, looks, charts, `//` a comment. `statements` is each one the engine read (`Cells.Statement`: `.type`, `.import`, `.table`, `.run` with its schedule, language, code and stored rows, `.column`, `.look`, `.chart`), its lines and its text, so a host shows them as controls and never parses the text; `text(.add(line))`, `.replace(lines, with:)` (a statement's `lines`, or a script's `codeLines` alone) and `.remove(statement)` are the file with its prelude edited, read again by the host so a new import is followed, and `written(.import("accounts", from: "accounts.cells"))` (or `.type`, `.column`, `.run` for a script's first line, `export` kept) the engine's own spelling of a line. `Cells.Palette` is the column colours of `syntaxes/palette.json` (`swift/scripts/palette.sh` writes it), each `Cells.Ink` a light and a dark, its `color` (and `Cells.Palette.column(i)`) a SwiftUI colour that follows the appearance. `Document(reading:at:)` follows a file's imports from the disk, a path from its folder read as it is now (a URL or a revision unreachable, a reference into it unchecked); `Document(reading:at:files:)` follows them through texts held by path.
- **Charts** (SPEC.md, Charts): `charts` is the file's chart fences in order, each a `Cells.Chart` (its kind, name, entries, title); `summary(chart:)` what one draws, read from the rows now (`Cells.ChartSummary`: places along its axis, series each with its shade, every value as exact decimal text, the currency, the rows left out, layers); `inferredChart` and `inferredSummary` the chart a file with none is drawn from, its entries what keeping it writes; `Cells.Chart.fence(kind:name:entries:)` the fence's own spelling.
- **Problems, by kind and place.** A cell that breaks its type is a `Problem` (`kind` `.type`, `.missing`, `.key`, `.formula`, `.reference` at `.cell(row:column:)`, the suite's kinds), its text kept and its value none, so the tool that can fix it can show it. Its `severity` is the engine's one rule: `.error` for what is wrong (a value breaking its type, a key repeated, a reference to no row, a formula that does not compute, a broken grammar), `.warning` for what is absent or behind (a value not written yet, a stored value its formula has moved past, a ragged row, a plain header's name). A `.cells` file's broken grammar (an unknown type, a row longer than the header, a prelude never closed, bytes that are not UTF-8) is its one refusal: `kind` `.grammar` at `.file`, `.header(column:)`, `.prelude(line:)` or `.record(row:)`, the document holding the file's text as it is and no rows. An untyped column is inferred, always optional (`inferred`, `type(of:)`).
- **Columns read in place** (`values(column:)`, a computed cell's value what its formula gives): Arrow's layout through the C Data Interface, never copied. `Values` is `.text`, `.int`, `.decimal` (128-bit mantissas at one scale), `.bool`, `.date` (days), `.time` (seconds), `.instant` (UTC at one unit) or `.choice` (indices into its words), each a `RandomAccessCollection` of optionals with its buffer at hand.
- **Written back byte for byte**: every unchanged record as read, the header until a type changes, the delimiter, line endings and final newline as found. A document is a value: a copy never shares an edit (the engine's doc is cloned on the first write to a shared one). Rows moved, added or taken out are the file read again by the engine.
- **The files people hold**: `Document(reading:as:)` takes a `Dialect`, `.cells` (the default, strict) or `.plain(delimiter:)`: a `.csv`, a `.tsv` or plain text, by the comma, the semicolon of a European export, the tab or the pipe, the one its first lines agree on when none is given (a Cells header's choices hold pipes no row does; a `.tsv` is tabs whatever its first line holds). A plain file's header cells are its columns' names, every type inferred, and nothing in its records is refused: a row of another width reads as blanks with a `.ragged` problem on a cell (its fields past the header kept and written back), a stray quote is text, a quote never closed runs to the end, a lone `\r` ends a line, a blank or repeated name is a `.name` problem at `.header(column:)`; a file that quotes every field (`"fuel","84.20"`, `layout.quotesAll`) has its edited cells and new rows quoted so too. `Cells.decode(data)` reads the bytes as UTF-8 with or without a byte order mark, UTF-16 (Excel's "Unicode text", found by its mark or by its zeroes) or Windows-1252, and says which (`Cells.Encoding`); `Cells.encode(text, encoding)` writes them back the same, mark included. Bytes that are none of them throw `Unreadable` with the reason (`byte 0x81 at 1204 begins no UTF-8 character, and is no Windows-1252 character either`), text an encoding cannot hold throws `Unwritable` naming the character. `decode(data, accepting: [.utf8])` is a cell's reading: its spec is UTF-8 alone.
- **Rows and columns**: `insertRows`, `removeRows`, `moveRows`, `set(_:)` for many cells at once, all of them or, when one is refused for holding a control character, none; `insertColumn`, `removeColumn` (the last one too), `moveColumn`, `rename(column:to:)` are the engine's `Doc::reshaped`, every other field of every row as written. A `.cells` file refuses a change it could not hold (a name another column has, a column a formula reads), throwing the engine's `Problem`.
- **Another format, when asked**: `written(delimiter:typed:)` is the text as a CSV or TSV (the header the names alone, every computed cell its value) or as a Cells file, the engine's `Doc::written_as`, a record kept as read where nothing changes it; `suggestedType(of:)` is what a writer converting a CSV declares (beyond the spec's inference, a few repeated words a choice and, in a file not separated by commas, `84,20` a number), `suggestedValue` a cell read by it, and `withTypesWritten()` the CSV as a new Cells file, decimal commas written with a point, the original untouched.
- **Spans** (`Cells.tokens`): what each part of a text is, the engine's own reading (fences, comments, statements, each header cell's name and type parts, every cell by its column, a formula's names by the column each reads), for a broken file too. An app colours a `.cells` file by them.
- **What a place is, for an editor**, as `cells lsp` answers it: `completions(in: text, at:)` what may be written at a UTF-16 offset of the text the document was read from (a cell's values, a type's names, a formula's columns, tables, rows and functions, each function with its call and what it gives, the prelude's statements), each `Cells.Completion` with the UTF-16 range it replaces; `hover(in: text, at:)` what is said there, in plain lines (a column, a cell's value and problem, a formula's name or function, a named type, a table), and the range it speaks of. The tables they name are the ones the document holds. `offers(column:)` is what a cell of a column may hold, to offer as it is typed: a choice's words, a boolean's two, the keys of the table a reference names.
- **The engine kept running, as a client of it**: `Cells.Daemon.connectOrStart(client:command:)` reaches the Cells engine over its socket (`~/Library/Application Support/Cells/engine.sock`), or starts it from the `cells` command an app carries when nothing answers; `serve(folder)` has it serve a folder, and `changes` is every file whose version changed, whoever wrote it, the engine's own writes (what a change reached, stored in every file reading it) included. The engine admits a client signed as Cells, so another app is refused at the greeting, told why (`DaemonError`). An app reads and writes its documents itself; the engine is the one process watching the disk.

`CellsTests` runs the whole conformance suite ([tests/](../tests/README.md), read where it lives, never copied) through the binding, its imports followed through the suite's own files, and the binding's own laws.

## CellsScripts

A Cells file's scripts read as TypeScript reads them, in the process: TypeScript's own language service run in JavaScriptCore, so a sandboxed app completes a script with no node and no child process. `try await TypeScriptService().completions(code:, at:, columns:)` answers what may be written at a UTF-16 offset of a script (`export default async function ({ last }) { … }`) as `ScriptCompletion`s (TypeScript's kind, the label, its modifiers, the text that goes in and the range it replaces), in TypeScript's order; `details(code:, at:, columns:, label:)` what one of them is (its signature, `(method) Body.json(): Promise<any>`, then its documentation), and `hover(code:, at:, columns:)` what is at a place, its text and the range it speaks of (`const res: Response`). The script is typed as the engine calls it: its default export's argument is a `CellsRun` (`last`, `rows`), each row a record of `columns`, its table's own (`last.` completes `date`, `rate`), and what it sees of the web is `fetch`, `Response`, `Headers`, `URL` and `console` (`Script/cells-script.d.ts`) over the ES2022 library. The service loads on the first question (about 90 ms), the first completion takes about 230 ms and each after a few. TypeScript 6.0.3 (Apache-2.0, its licence and notices beside it in `TypeScript/`), the last line with the language service in JavaScript, fetched and digest-checked by `swift/scripts/typescript.sh`.
